# RAM Cloud Security — Empirical Experiment Plan

## 1. Experimental Overview

This document formalizes the comparative evaluation plan for RAM Cloud Security across progressively sophisticated detection paradigms.

```
+-----------------------------------------------------------------------------------+
|               PLANNED EXPERIMENTAL COMPARISON MATRIX                             |
+-----------------------------------------------------------------------------------+
| Baseline A: Deterministic Rules Only (Phase 2) [COMPLETED]                        |
| Baseline B: Unsupervised Machine Learning Anomaly Detection Only (Phase 4)        |
| Candidate:  Linear Hybrid Combination (Rules + ML Anomaly Scores) (Phase 5)       |
| Proposed:   Identity-Aware, Temporal Evidence Fusion with Calibration (Phase 6)   |
+-----------------------------------------------------------------------------------+
```

---

## 2. Detailed Experiment Specifications

### 2.1 Baseline A: Deterministic Rules Only
- **Status:** **COMPLETED** (Evaluated in Phase 2)
- **Input:** Stream of `NormalizedEvent` objects.
- **Model:** Deterministic `RuleEngine` (11 rules covering IAM, Configuration, Exposure).
- **Observed Metrics (Real Stratus Dataset):**
  - Event Precision: 54.76% (Def 1) / 30.95% (Def 2)
  - Event Recall: 2.01% (Def 1) / 6.07% (Def 2)
  - F1-Score: 0.0387 (Def 1) / 0.1016 (Def 2)
  - Technique-Level Recall: 20.48% (17 / 83 attack runs detected)
  - Time-to-First-Alert: 6.0 seconds
- **Observed Failure Mode:** Misses 97.99% of attack events (discovery, credential access).

---

### 2.2 Baseline B: Machine Learning Anomaly Detection Only
- **Status:** **PLANNED (Phase 4)**
- **Input:** $N \times D$ Feature Matrix generated by Phase 3 pipeline.
- **Algorithms Evaluated:**
  - Isolation Forest (iForest)
  - One-Class Support Vector Machine (OC-SVM)
  - Local Outlier Factor (LOF)
- **Training Strategy:** Fit on benign/operational baseline slices; evaluate anomaly score thresholding across attack detonation sequences.
- **Target Metrics:** Precision, Recall, F1-Score, PR-AUC, False Positive Rate.
- **Expected Failure Mode:** Probabilistic false alarms on unmodeled routine administrative bursts; lack of deterministic grounding for hard violations.

---

### 2.3 Candidate Model: Linear Rule + ML Combination
- **Status:** **PLANNED (Phase 5)**
- **Input:** Combined stream of Rule `SecurityFinding` objects and ML Anomaly Scores.
- **Logic:** Union of rule triggers and ML threshold exceedances without temporal context.
- **Target Metrics:** Precision, Recall, F1, Alert Volume.
- **Expected Failure Mode:** High alert volume from additive false alarms; uncalibrated confidence.

---

### 2.4 Proposed Model: Identity-Aware & Temporal Evidence Fusion
- **Status:** **PLANNED (Phase 6)**
- **Input:** Normalized events, rule evidence, behavioral feature vectors, identity context, and sliding temporal windows.
- **Logic:** Fuses evidence across time windows per identity; evaluates threat progression confidence using calibrated scoring.
- **Target Metrics:** Multi-stage attack chain detection rate, event precision/recall, time-to-incident detection, reduction in operator false alarms.
- **Ablation Studies:**
  - Ablation 1: Fusion without temporal sliding windows.
  - Ablation 2: Fusion without identity context.
  - Ablation 3: Fusion without deterministic rule signals.

---

## 3. Evaluation Artifact Outputs for Each Experiment
Each completed experiment must generate:
1. Structured JSON metrics under `experiments/results/<experiment_name>_metrics.json`.
2. Confusion matrix and PR curves under `reports/figures/experiments/`.
3. Dedicated experimental report under `docs/<PHASE>_<EXPERIMENT>_REPORT.md`.
