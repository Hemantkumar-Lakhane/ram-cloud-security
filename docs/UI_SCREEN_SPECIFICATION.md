### A. Global Application Shell
- **Purpose:** Persistent container providing navigation, environment context, global search, notification summary, and breadcrumb routing.
- **Header Elements:**
  - System Brand: `RAM Cloud Security [v0.2.0-research]`.
  - Active Environment Pill: `AWS Lab Capture (invictus-ir/aws_dataset) — 2,900 Records`.
  - Global Search Input: `Search identities, assets, rules, events (Ctrl+K)`.
  - System Health & Alert Counter: `42 Total Alerts | 0 Unhandled Critical`.
- **Sidebar Structure:** Collapsible 2-tier tree grouped by operational domains (Security, Environment, Posture, Detection, Research, Response, Admin).
- **Responsive Behavior:**
  - $w \ge 1280\text{px}$: Sidebar expanded ($240\text{px}$).
  - $1024\text{px} \le w < 1280\text{px}$: Sidebar auto-collapses to icon-only rail ($64\text{px}$) with hover tooltips.
  - $w < 1024\text{px}$: Sidebar hidden behind sliding hamburger drawer.

### B. Security Overview Dashboard (`/security/overview`)
- **Primary Purpose:** High-signal, calm operational posture summary answering: *"What is the active security state of the monitored environment?"*
- **Layout Architecture (Anti-Slop Restrained Design):**
  - **Zone 1: Environment Status Banner (Single Compact Strip, not a 15-card grid):**
    - Environment Identifier: `context.environment_name` (`AWS Lab Capture — invictus-ir/aws_dataset`).
    - Telemetry Window: `context.time_range_start` to `context.time_range_end` (`stats.duration_minutes` mins).
    - Status Indicators: `stats.active_findings_count` Unhandled Alerts | `stats.active_principals_count` Monitored Actors | `stats.services_count` AWS Services.
  - **Zone 2: Telemetry Dynamics & Risk Split ($60\% / 40\%$):**
    - *Left Panel (Ingestion Velocity):* Dynamic rendering of Figure 09 (Event Arrival Rate Density) showing burst vs baseline rate.
    - *Right Panel (Operational Breakdown):* Dynamic rendering of Figure 01 (4-Tier Activity Distribution) and Figure 07 (API Execution Success vs Error).
  - **Zone 3: Triage Priorities:**
    - Live triage table of top unhandled findings generated by the active rule engine, sorted by severity.
- **Data Source Contracts:** `experiments/results/rule_baseline_metrics.json`, `experiments/results/eda_summary.json`.
- **State Handling:**
  - *Loading:* Subtle structural skeleton matching final table height.
  - *Empty:* "No telemetry events ingested in current session."

### C. Security Findings Workspace (`/security/findings`)
- **Purpose:** Searchable, filterable triage workspace for all security alerts.
- **Toolbar & Filter Controls:**
  - Severity Filter: Multi-select (`Critical`, `High`, `Medium`, `Low`).
  - Rule Domain: `All Domains`, `IAM Rules`, `Configuration Rules`, `Exposure Rules`.
  - Detection Source: `Rule Engine (Baseline A) [Active]`, `Statistical Anomaly [Phase 4: Not Evaluated]`, `Behavioral Sequence [Phase 5: Not Evaluated]`.
  - Search: Free-text filter matching finding title, actor, or resource ARN.
- **Data Table Columns:**
  1. *Severity Badge* (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW` with standardized glyphs).
  2. *Finding ID & Title* (Dynamic from `SecurityFinding.title`).
  3. *Detection Engine* (`RULE: RULE-CFG-001`).
  4. *Actor / Principal* (Sanitized ID from `identity_mapping`: `IAMUser-01`, `Role-01`).
  5. *Target Resource* (`SecurityFinding.resource_id`).
  6. *Event Time (UTC)* (`SecurityFinding.timestamp`).
  7. *Triage Status* (`NEW`, `IN_REVIEW`, `SUPPRESSED`, `RESOLVED`).
  8. *Action Link* (`Investigate ->`).
- **Data Source:** `RuleEngine.evaluate_event()` stream output over ingested dataset.

### D. Finding Forensic Detail (`/security/findings/:id`)
- **Structure:** 2-column forensic workspace ($65\% / 35\%$ layout).
- **Left Column (Forensic Context & Evidence):**
  1. *Finding Header:* Title, Severity Badge, Confidence Score (`SecurityFinding.confidence`).
  2. *Detection Rationale:* Specific conditions triggered from `SecurityFinding.description`.
  3. *Evidence Sources Accordion:*
     - **Rule Evidence [Active]:** Rule ID, condition graph, triggering event fields.
     - **Identity Baseline Evidence [Active]:** Principal service access profile from Fig 13.
     - **Statistical Anomaly Evidence [Phase 4: Not Evaluated]:** Baseline deviation placeholder.
     - **Behavioral Sequence Evidence [Phase 5: Not Evaluated]:** Multi-event progression placeholder.
  4. *Raw Normalized Event Inspector:* Formatted JSON viewer displaying [`NormalizedEvent`](file:///c:/Users/lakha/ml_ram_antivirous/src/common/models.py#L19-L46) dictionary.
- **Right Column (Context & Response Actions):**
  1. *Affected Asset Card:* Resource ARN, AWS Service, Region, First/Last Seen.
  2. *Actor Identity Card:* Sanitized ID (`IAMUser-01`), Principal Type, Source IP, User-Agent provenance category.
  3. *Recommended Response Card:* Automated playbook recommendation with explicit tri-state badge:
     - `Recommendation` (Automated playbook recommendation).
     - `Dry Run Preview` (Simulated local execution).
     - `Live Action` (Disabled / Requires safety override).
  4. *Action Trigger Button:* `Preview Remediation [Dry Run]`.

### E. Incident Investigation Workspace (`/security/investigation`)
- **Purpose:** Multi-signal temporal correlation workspace connecting actors, APIs, resources, and threat progressions.
- **Interactive Controls:**
  - Principal Selector: Choose from 14 sanitized IAM actors (`IAMUser-01`, `Role-01`, etc.).
  - Time Range Slider: Zoom in/out across the 55.5-minute timeline.
- **Visual Investigation Canvas:**
  - **Top Swimlane:** Temporal progression across MITRE ATT&CK tactics (ref Figure 14). Includes clear disclaimer: *"Chronological ordering reflects execution sequence across independent emulation runs"*.
  - **Middle Heatmap:** Service access intensity over time for selected actor (ref Figure 12).
  - **Bottom Event Stream:** Synchronized table of raw CloudTrail events corresponding to the active zoom window.

### F. Cloud Assets Inventory & Detail (`/environment/assets`)
- **List View:** Table of all unique cloud resources discovered across the 2,900 CloudTrail events (EC2 instances, S3 buckets, IAM roles, KMS keys, SSM parameters).
- **Asset Detail View:**

### G. Identities & IAM Principal Monitor (`/environment/identities`)
- **List View:** Inventory of all 14 IAM actors with deterministic sanitized tokens (`IAMUser-01`, `Role-01`, `AWSService-01`).
- **Principal Profile Detail View:**
  - Activity Volume: Total events, error count, distinct services accessed.
  - Figure 13 Embedded View: Service access percentage profile (Panel B).
  - Behavioral Baseline Status: `Baseline Computed (Rule Baseline A)`.
  - Linked Findings: Alerts triggered by this principal.

### H. Telemetry Event Explorer (`/detection/events`)
- **Purpose:** Full-featured raw telemetry explorer for all 2,900 ingested CloudTrail events.
- **Filter Bar:** Service, Event Name, Actor, Source IP, Is Error (`True`/`False`), Activity Tier.
- **Data Table:** Fast virtualized table with row expansion revealing normalized dictionary and raw request parameters.
- **Export Action:** Export filtered subset to JSON / CSV.

### I. Threat Activity & Detonation Correlation (`/detection/threats`)
- **Purpose:** Correlates telemetry against the 83 Stratus Red Team emulation runs.
- **Views:**
  - Detonation Run Inventory: 83 unique runs grouped by technique name (`aws.defense-evasion.cloudtrail-stop`, `aws.credential-access.ec2-get-password-data`).
  - Technique Coverage Summary: 17 runs detected by Baseline A (20.48% recall); 66 runs missed (documenting the discovery/stealth gap for Phase 4 ML).

### L. Safe Response Center (`/response/center`)
- **Safety Defaults Banner:** `SAFETY LOCK ENGAGED: DRY_RUN = True | LIVE_EXECUTION = Disabled`.
- **Response Recommendation Queue:**
  - Finding reference, proposed action (`aws:cloudtrail:StartLogging`, `aws:iam:DeactivateAccessKey`), target resource.
  - Preview Action Diff: Visual before/after state simulation.
  - Human Approval Gate: Interactive authorization button with confirmation modal requiring explicit reason logging.
- **Simulated Execution Console:** Logs the dry-run response without contacting real AWS endpoints.
